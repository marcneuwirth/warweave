# ADR-0005 — A Common unit type never matches a branch unit type on that branch's signature axis

**Status:** accepted · **Ticket:** [#3](https://github.com/marcneuwirth/warweave/issues/3) · **Spec:** §1.1, §13, §16

## Context

Setting movement speeds forced the question directly: the Common cavalry chassis and the Beast gateway are both "fast", and whichever is faster owns the top of the speed ladder. Beast's stated identity is *Overwhelm* — mobility, predation, target access.

## Decision

> A Common unit type never matches a branch unit type on that branch's signature axis.

The originating instance: Direwolves at **7.5 m/s** against the Common cavalry at 6.5. Beast owns the top of the speed ladder outright, and the Beast doctrine's speed grant reads correctly as a doctrine payoff rather than as parity with a no-commitment purchase.

## Why

Common is available from round 1 with no gate and no investment. If Common can match a branch on the axis that branch is *named for*, the branch's identity is purchasable without commitment, and the affinity system stops describing anything. The rule generalises: it is a reusable test rather than a single speed ruling.

## Consequences

- Applied later to rule that a Common unit type owns **no role at all** (ADR-0043) — the strongest form of this rule, and the one the role scheme needs.
- Gives the technology audit and the Common-redundancy question a concrete test to apply rather than a taste judgement.
- Common's positive definition — *the R1–R4 army* — is [ADR-0051](0051-common-is-the-r1-r4-army.md).
